# ドキュメント運用

`Docs/` は、AIと人が実装判断を共有するための成果物置き場です。説明のための長文ではなく、判断に必要な核心だけを残します。

## 標準構成

```text
Docs/
├── 01-brief/
│   └── template.md
├── 02-spec/
│   └── template.md
├── 03-build/
│   └── template.md
├── 04-verify/
│   └── template.md
├── improvements.md
├── status.md
└── README.md
```

## 4フェーズ

### `01-brief`

作るものの輪郭を決めます。最低限、次の3点が分かれば十分です。

- 何を作るか
- 誰のためか
- 何をやらないか

### `02-spec`

仕様の核心を残します。標準で書くのは次の3点です。

- 意思決定
- 制約
- 受け入れ条件

必要な案件だけ、`主要フロー` と `例外` を足します。

### `03-build`

実装中にあとで見返す価値がある情報だけを残します。

- 実装メモ
- 判断ログ
- 未解決事項

### `04-verify`

検証と出荷判断に必要な情報だけを残します。

- 実施した確認
- 結果
- 残課題
- 出荷可否

## 書き方の原則

- 1ファイルを短く保つ
- AIが推測できる一般論は書かない
- 実装判断に効く記述を優先する
- 同じ説明を複数ファイルに書かない

## 補助運用

### `draft/` と `fixed/`

必要なときだけ使います。全案件で必須ではありません。

- `draft/`: 検討中やレビュー前のもの
- `fixed/`: 合意済みで次の判断の基準にしたいもの

### `status.md`

任意のローカルメモです。継続作業でメモが欲しいときだけ使います。Git 管理外なので、共有前提では扱いません。

### `improvements.md`

基盤改善の気づきを短く残すためのファイルです。旧 `Docs/feedback/` より軽く使う前提です。
