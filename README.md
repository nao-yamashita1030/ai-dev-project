# AI駆動開発基盤リポジトリ

AIで開発を進めるための、軽量な基盤リポジトリです。長い工程表や網羅的な仕様書ではなく、実装判断に必要な核心テキストだけを残す運用を前提にしています。

## このリポジトリの考え方

- `rules`: 短い恒久ルールだけを置く
- `skills`: 反復ワークフローだけを置く
- `Docs`: 意思決定、制約、受け入れ条件などの成果物だけを置く

README には入口だけを書き、詳細な運用は `Docs/` と `.cursor/rules/` に寄せます。

## 使い方

1. リポジトリをフォークまたはクローンする
2. Cursor で開く
3. 作業の意図に応じて、最初に次のどちらかを伝える

```text
設計モードスタート
実行モードスタート
```

## モード

### 設計モード

要件整理、仕様確定、実装方針の決定に使います。主な成果物は短い仕様書です。

### 実行モード

実装、検証、修正、必要最小限のドキュメント更新に使います。仕様が足りないときだけ、必要箇所を補います。

## フェーズ

固定の大段階は次の4つです。

1. `Brief`: 何を作るか、誰のためか、何をやらないか
2. `Spec`: 決定事項、制約、受け入れ条件、必要なら主要フローと例外
3. `Build`: 実装メモ、判断ログ、未解決事項
4. `Verify`: 検証結果、確認観点、出荷判断

この4フェーズは直列前提ではありません。`Spec -> Build -> Verify` を小さく反復する運用を想定しています。

## ドキュメント方針

- 長文の説明より、実装判断に効く情報を優先する
- 標準で残すのは `意思決定`、`制約`、`受け入れ条件`
- `主要フロー` と `例外` は迷いやすい案件だけ追加する
- `draft/` や `fixed/` は必要なときだけ作る

ドキュメント構成は [Docs/README.md](Docs/README.md) を参照してください。

## 作業メモ

- `Docs/status.md` は任意のローカルメモです
- Git 管理外なので、基盤の成立条件にはしません
- 継続作業でメモが欲しい場合だけ使います

## 改善記録

基盤自体の改善案は [Docs/improvements.md](Docs/improvements.md) に短く残します。旧 `Docs/feedback/` は互換目的で残していますが、新規記録先としては推奨しません。
