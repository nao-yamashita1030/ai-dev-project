# コミットメッセージのルール

このリポジトリでは、簡潔な Conventional Commits 形式を使います。

## 基本形式

```text
<type>: <subject>
```

例:

```text
docs: READMEを簡潔な運用モデルに更新
refactor: 4フェーズ前提にルール構成を整理
chore: project skill を追加
```

## 使う type

- `feat`: 新機能
- `fix`: 不具合修正
- `docs`: ドキュメント変更
- `refactor`: 振る舞いを変えない整理
- `test`: テスト追加や更新
- `chore`: 設定や補助資産の変更
- `perf`: 性能改善

## subject の原則

- 日本語で簡潔に書く
- 変更の目的が分かるように書く
- 句読点を付けない
- 不要に長くしない

## 本文

必要なときだけ追加し、変更理由や補足を短く書きます。
